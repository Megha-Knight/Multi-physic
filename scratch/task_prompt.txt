real face plane, consistent per face kind. derived_region_visual_builder_ui_main's
inDir = f.n().multiply(-1.0) is also correct given that. So the bug is NOT in the
frame/direction math — it is most likely in the VALUES being fed into
topology_derived_face_ui_main's depth/radius/localCenter fields, computed in
hole_topology_builder_ui_main (not yet reviewed).

Before writing a fix, read hole_topology_builder_ui_main in full and answer:

    SAME functions that actually cut the real cavity (in hole_cuboid_builder_ui_main

    this project has already had two confirmed bugs (cube center/size, and the
    circular-only wall above) caused by exactly this pattern: a visual/overlay
    piece reimplementing a formula instead of calling the function that builds
    the real geometry. Check this first before checking anything else.

    f.origin().add(f.u().multiply(localCenter.X)).add(f.v().multiply(localCenter.Y))

derive these values from the same source the real cavity cutter uses, rather than
